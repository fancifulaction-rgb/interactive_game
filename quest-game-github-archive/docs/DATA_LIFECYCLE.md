# Данные на сервере: что создаётся и что удалять

Документ для обсуждения политики хранения при удалении игры, команды или архивации события.

## 1. После создания игры (админ-панель → «Создать игру»)

| Где | Что | Примечание |
|-----|-----|------------|
| `games` | строка: `id`, `code`, `title`, `theme`, `mask_board`, `total_time_sec`, `per_question_time_sec`, `scoring`, `finish_page_type`, … | Одна запись на игру |
| Storage | обычно **ничего** | Медиа появляются при редактировании вопросов / логотипе квеста |

Глобальные настройки (`settings`, `themes`) **не привязаны** к игре — не удаляются с игрой.

---

## 2. После добавления вопросов в редакторе игры

| Где | Что |
|-----|-----|
| `questions` | вопросы: текст, тип, варианты, ответы, очки, подсказки, `media_url` |
| Storage `question-media` | файлы к вопросам (если загружали) |

---

## 3. После регистрации команды (`/team/register`)

| Где | Что |
|-----|-----|
| `teams` | `game_id`, имя, аватар (`avatar` / URL) |
| Storage `avatars` или `answer-media` | аватар команды (зависит от загрузчика) |
| `players` | сессии/игроки по `game_id`, `team_name`, `current_question` (если используется потоком) |

Сообщения админа (`messages`, `message_recipients`, `message_reads`) появляются **позже**, когда админ шлёт уведомления в игру.

---

## 4. Во время и после прохождения квеста

| Где | Что |
|-----|-----|
| `answers` | ответы команд: текст/JSON, `is_correct`, очки, время, `media_urls` |
| Storage `answer-media` | фото/видео ответов |
| `team_scores` | агрегат по команде для табло |
| `game_state` | состояние сессии (`current_state`, `player_data`) |
| `messages` + связанные | рассылки и прочтения |

---

## 5. Удаление игры (текущее поведение в коде)

**Edge Function `delete-game`** (если развёрнута): удаляет медиа из Storage, затем `answers` → `teams` → `questions` → `games`.

**Клиентский fallback** (`deleteGameCompletely`): `DELETE FROM games` — срабатывает **CASCADE** на:

- `teams`, `players`, `questions`, `answers`, `game_state`, `team_scores`, `messages` (и каскадом `message_recipients`, `message_reads`).

**Не удаляется автоматически:**

- файлы в Storage (остаются «сиротами», если не вызывать Edge Function);
- глобальные `settings`, `themes`;
- учётная запись админа в `auth.users`.

---

## 6. Рекомендации для обсуждения

| Данные | При удалении игры | Комментарий |
|--------|-------------------|-------------|
| `games`, `questions`, `teams`, `answers`, `game_state`, `team_scores`, сообщения | **Удалять** | Логично для GDPR/очистки тестов |
| Storage (медиа игры) | **Удалять** | Нужна Edge Function или отдельный скрипт по префиксу `game_id` |
| Агрегированная статистика / отчёты | **Хранить** | Таблица `event_archive` (миграция 014): снимок при «Завершить игру», CSV в AdminPanel |
| Логи Edge Functions / Supabase | **Хранить** | Операционные, не в приложении |
| `settings` / `themes` | **Не трогать** | Общие для всей платформы |

---

## 7. Следующие шаги (по желанию)

1. Развернуть `delete-game` на Supabase: `supabase functions deploy delete-game`.
2. Добавить очистку Storage по `game_id` в клиентский fallback или RPC.
3. Ввести «мягкое удаление» (`games.deleted_at`) + архив для отчётов корпоративов.
