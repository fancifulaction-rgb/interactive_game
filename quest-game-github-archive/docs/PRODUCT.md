# Продукт Quest Game

## Назначение

**Quest Game** — платформа для проведения **командных интерактивных квестов** на офлайн-мероприятиях (корпоративы, тимбилдинги, праздники). Команды играют со смартфонов; организатор управляет игрой с ноутбука и выводит табло на проектор.

## Целевая аудитория

| Роль | Кто | Потребности |
|------|-----|-------------|
| **Организатор / админ** | HR, ведущий, IT на площадке | Создать игру, вопросы, медиа; пауза; сообщения; табло; экспорт |
| **Команда / капитан** | Гости 20–60 лет | Простая регистрация по коду, понятные вопросы, фото/видео в ответах |
| **Зритель** | Зал | Табло с очками и аватарами на экране |

## Отличие от «квиза на скорость» (Kahoot-подобные)

| Аспект | Quest Game | Kahoot / QuizLive |
|--------|------------|-------------------|
| Темп | Асинхронный квест, команда идёт в своём ритме | Синхронные раунды по таймеру ведущего |
| Ответы | Текст, выбор, **фото/видео/аудио** | В основном выбор варианта |
| Оценка | Формула очков + подсказки со штрафами; настраиваемая проверка ответов (IMP-LOG-022, см. `guides/ANSWER_GRADING.md`); ручная модерация — фаза 2+ | Авто по ключу / времени |
| Команды | Центральная сущность `teams` | Часто индивидуальные игроки |

## Основные возможности (текущая версия 1.2.16)

### Администратор

- Вход по email/паролю (Supabase Auth).
- Список игр, создание, удаление (CASCADE + опционально Edge `delete-game`).
- Редактор вопросов: тип, варианты, медиа, подсказки, штрафы, сложность, таймер на вопрос.
- Настройки игры: тема, маскированное табло, общее время, формула `scoring`, тип финальной страницы.
- Пауза игры для всех (`game_state.is_paused`).
- Рассылка сообщений командам (`messages`).
- Табло админа, детальное табло, экспорт Excel.
- Глобальные настройки и темы оформления.

### Игрок (команда)

- Регистрация по **коду игры** (4–6 символов), имя команды, опционально аватар.
- Прохождение вопросов по порядку, таймеры, подсказки.
- Отправка ответа с медиа (сжатие изображений на клиенте).
- Уведомления от админа.
- Табло и страницы поздравления после финиша.
- Учёт очков с оптимистичным UI и фоновой синхронизацией.

## Пользовательские сценарии (happy path)

### Сценарий A: Подготовка мероприятия

1. Админ создаёт игру в `/admin/panel`, получает код (например `26D4A6`).
2. Добавляет вопросы в `/admin/game/:id/edit`, при необходимости загружает медиа в `question-media`.
3. Проверяет тему и настройки scoring.
4. Открывает `/scoreboard-admin/:code` на проекторе.

### Сценарий B: День мероприятия

1. Команды открывают `/team/register`, вводят код, регистрируются.
2. Переходят в `/game/:code`, отвечают на вопросы.
3. По завершении — `/congratulation/:code` или табло `/scoreboard/:code`.
4. Аватары догружаются в фоне после игры (jitter 0–15 с).

### Сценарий C: Завершение

1. Админ смотрит результаты, экспортирует Excel.
2. При необходимости удаляет тестовую игру (см. DATA_LIFECYCLE).

## Ограничения и допущения продукта

- Интернет на площадке желателен (Supabase cloud). Offline-first **не** реализован (см. IMP-UX-003 в каталоге).
- Один Supabase-проект на инсталляцию; мультитенантность на уровне БД не выделена.
- RLS упрощён (широкие политики) — для публичного anon-доступа игроков; см. SECURITY.
- Edge Functions могут быть не задеплоены — работает fallback с клиента.

## Метрики успеха на мероприятии

- Регистрация команды &lt; 30 с на типичном LTE/Wi‑Fi.
- Ответ с фото не «висит» UI (оптимистичный переход к следующему вопросу).
- Табло обновляется без заметных пауз для зала.
- До **100** одновременных команд без массовых 429 (при адекватном плане Supabase).
